> **टीएल;डीआर**
> * **किताब का सवाल:** स्ट्रिंग पर तीन प्रकार के संपादन किए जा सकते हैं: एक अक्षर जोड़ना, एक अक्षर हटाना या एक अक्षर बदलना। दो स्ट्रिंग्स दिए जाने पर, यह जांचने के लिए एक फ़ंक्शन लिखें कि क्या वे एक संपादन (या शून्य संपादन) की दूरी पर हैं।
> * **इष्टतम समाधान:** दोनों स्ट्रिंग्स की लंबाई की तुलना करें। यदि लंबाई का अंतर १ से अधिक है, तो तुरंत `false` लौटाएं। समान लंबाई पर अधिकतम एक बदलाव और लंबाई में १ का अंतर होने पर दो पॉइंटर्स द्वारा एक पास में $O(N)$ समय और $O(१)$ अतिरिक्त स्पेस में जांचें।
> * **रियल-वर्ल्ड सिस्टम:** सर्च इंजन में टाइपो सुधार, डीएनए अनुक्रम म्यूटेशन और टर्मिनल कमांड लाइन सुझाव इंजन।

## १. किताब का सवाल और परीक्षण मामले

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १.५) में पूछा गया है:

*"स्ट्रिंग पर तीन प्रकार के संपादन किए जा सकते हैं: एक अक्षर जोड़ना, एक अक्षर हटाना या एक अक्षर बदलना। दो स्ट्रिंग्स दिए जाने पर, यह जांचने के लिए एक फ़ंक्शन लिखें कि क्या वे एक संपादन (या शून्य संपादन) की दूरी पर हैं।"*

**परीक्षण मामले:**
* `pale, ple -> true` ('a' को हटाना या जोड़ना)
* `pales, pale -> true` ('s' को जोड़ना या हटाना)
* `pale, bale -> true` ('p' को 'b' से बदलना)
* `pale, bake -> false` (दो बदलाव: 'p'->'b' और 'l'->'k')

## २. सरल दृष्टिकोण और इसकी कमियां

एक सरल दृष्टिकोण डायनामिक प्रोग्रामिंग के माध्यम से लेवेनश्टाइन दूरी (Levenshtein Distance) मैट्रिक्स की गणना करना हो सकता है:
* **समय जटिलता:** $O(N \times M)$ जहां $N$ और $M$ स्ट्रिंग्स की लंबाइयां हैं।
* **मेमोरी जटिलता:** $O(N \times M)$ अतिरिक्त स्पेस।

जब हमें केवल यह जांचना हो कि संपादन दूरी $\le १$ है, तो पूरी मैट्रिक्स की गणना करना अनावश्यक ओवरहेड है। हम इसे रैखिक समय में हल कर सकते हैं।

## ३. इष्टतम दो-पॉइंटर कार्यप्रणाली

हम दो पॉइंटर्स `index1` और `index2` का उपयोग करके एक ही लूप में जांच पूरी करते हैं:
१. जब तक दोनों पॉइंटर्स स्ट्रिंग की सीमा के भीतर हैं, अक्षरों की तुलना करें।
२. यदि कोई बेमेल अक्षर मिलता है:
   * यदि पहले से कोई बेमेल मिल चुका है (`foundDifference == true`), तो सीधे `false` लौटाएं।
   * `foundDifference = true` चिह्नित करें।
   * यदि दोनों स्ट्रिंग्स की लंबाई समान है, तो दोनों पॉइंटर्स को आगे बढ़ाएं (बदलने का मामला)।
   * यदि लंबाई भिन्न है, तो केवल लंबी स्ट्रिंग के पॉइंटर को आगे बढ़ाएं (जोड़ने/हटाने का मामला)।
३. यदि लूप बिना किसी अतिरिक्त बेमेल के समाप्त होता है, तो `true` लौटाएं।

## प्रोडक्शन कार्यान्वयन

```java
public class OneAway {
    /**
     * जांचता है कि क्या दो स्ट्रिंग्स शून्य या एक संपादन की दूरी पर हैं।
     * समय जटिलता: O(N) जहां N छोटी स्ट्रिंग की लंबाई है।
     * स्पेस जटिलता: O(1) सहायक स्पेस।
     */
    public static boolean oneEditAway(String first, String second) {
        if (Math.abs(first.length() - second.length()) > 1) {
            return false;
        }

        // छोटी और लंबी स्ट्रिंग की पहचान करें
        String s1 = first.length() < second.length() ? first : second;
        String s2 = first.length() < second.length() ? second : first;

        int index1 = 0;
        int index2 = 0;
        boolean foundDifference = false;

        while (index2 < s2.length() && index1 < s1.length()) {
            if (s1.charAt(index1) != s2.charAt(index2)) {
                if (foundDifference) return false;
                foundDifference = true;

                if (s1.length() == s2.length()) {
                    index1++;
                }
            } else {
                index1++;
            }
            index2++;
        }

        return true;
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| समय जटिलता | `O(N)` | स्ट्रिंग्स को एक ही पास में स्कैन करता है जहां $N = \min(|first|, |second|)$। |
| सहायक मेमोरी | `O(१)` | केवल पूर्णांक पॉइंटर रजिस्टरों का उपयोग, बिना किसी हीप आवंटन के। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: अस्पष्ट खोज और सीएलआई सुझाव

१. **सर्च ऑटोकम्प्लीट और टाइपो टॉलरेंस (इलास्टिकसर्च / ल्यूसीन):** ल्यूसीन संपादन दूरी १ या २ के आधार पर स्वचालित रूप से सही शब्द सुझाने के लिए ऑटोमेटा बनाता है।
२. **गिट और टर्मिनल कमांड सुधार:** `git stauts` लिखने पर गिट दूरी १ वाले कमांड की जांच करके `git status` का सुझाव देता है।
३. **बायोइन्फॉर्मेटिक्स:** जीनोमिक अनुक्रमों में एकल बिंदु म्यूटेशन की पहचान।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **समान स्ट्रिंग्स (`"pale", "pale"`):** `true` लौटाता है (शून्य संपादन)।
२. **खाली स्ट्रिंग्स (`"", ""`):** `true` लौटाता है।
३. **लंबाई का अंतर $\ge २$ (`"p", "pale"`):** बिना स्ट्रिंग स्कैन किए $O(१)$ में समाप्त।
४. **शून्य इनपुट:** सुरक्षित जांच `if (first == null || second == null) return false;`।
