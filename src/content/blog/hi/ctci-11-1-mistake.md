> **टीएल;डीआर**
> * **किताब का सवाल:** निम्नलिखित कोड में गलती ढूंढें: `unsigned int i; for (i = 100; i >= 0; --i) printf("%d\n", i);`
> * **मुख्य त्रुटियां और मूल कारण:** (१) **अनसाइंड अंडरफ्लो इनवेरिएंट**: एक `unsigned int` हमेशा गैर-ऋणात्मक होता है ($i \ge 0$ हमेशा सत्य रहता है)। $i = 0$ के बाद `--i` करने पर वह अंडरफ्लो होकर `UINT_MAX` ($4,294,967,295$) बन जाता है, जिससे इनफिनिट लूप बन जाता है; (२) **फॉर्मेट विसंगति**: `%d` साइन्ड इंटीजर के लिए है, जबकि अनसाइंड के लिए `%u` का उपयोग होना चाहिए।
> * **समाधान:** `int i` (साइंड इंटीजर) का उपयोग करना।
> * **रियल-वर्ल्ड सिस्टम:** लिनक्स कर्नल सुरक्षा बग्स और एवियोनिक्स टाइमर ओवरफ्लो।

## १. किताब का कोड और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या ११.१) में पूछा गया है:

```c
unsigned int i;
for (i = 100; i >= 0; --i)
    printf("%d\n", i);
```

## २. अनसाइंड प्रकार में मॉड्यूलर अंकगणित

सी/सी++ में अनसाइंड अंकगणित $2^W$ के सापेक्ष चक्रीय होता है:
$$\text{परिणाम} = (\text{मान}) \pmod{2^W}$$

जब $i = 0$ होता है:
$$0 - 1 \equiv 4,294,967,295\ (\text{UINT\_MAX})$$

चूंकि $4,294,967,295 \ge 0$ है, इसलिए `i >= 0` कभी गलत नहीं होता और लूप कभी समाप्त नहीं होता।

## प्रोडक्शन कार्यान्वयन

```c
#include <stdio.h>

void printNumbersSigned(void) {
    for (int i = 100; i >= 0; --i) {
        printf("%d\n", i);
    }
}

void printNumbersUnsigned(void) {
    for (unsigned int i = 100; i > 0; --i) {
        printf("%u\n", i);
    }
    printf("%u\n", 0);
}
```

## त्रुटि मैट्रिक्स और स्टैटिक एनालिसिस

| दोष | गंभीरता | परिणाम | कंपाइलर चेतावनी |
|---|---|---|---|
| `unsigned int i >= 0` | क्रिटिकल | इनफिनिट लूप / प्रोसेस हैंग। | `-Wtype-limits` (GCC / Clang). |
| `%d` बनाम `%u` | मध्यम | बड़े मानों पर अपरिभाषित व्यवहार। | `-Wformat` (GCC / Clang). |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: सुरक्षा कमजोरियां

१. **लिनक्स कर्नल CVE-2016-0728:** ३२-बिट संदर्भ काउंटर के ओवरफ्लो होने से रूट विशेषाधिकार प्राप्त करने की सुरक्षा खामी।
२. **बोइंग ७८७ इलेक्ट्रिक बस:** २४८ दिनों के निरंतर संचालन के बाद ३२-बिट टाइमर ओवरफ्लो।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **कंपाइलर ऑप्टिमाइजेशन (`-O3`):** कंपाइलर जांच को हटाकर अनकंडीशनल अनंत जंप निर्देश उत्पन्न कर सकता है।
२. **सीआई/सीडी नियम:** बिल्ड विफलताओं के लिए `-Wall -Wextra -Werror` सक्षम करना।
