> **टीएल;डीआर**
> * **किताब का सवाल:** बताएं कि ऑब्जेक्ट डिक्लेरेशन क्या है और जावा में पास-बाय-वैल्यू और पास-बाय-रेफरेंस के बीच क्या अंतर है?
> * **मुख्य समाधान:** **स्टैक रेफरेंस बाइंडिंग और सख्त पास-बाय-वैल्यू**:
>   1. **डिक्लेरेशन बनाम इंस्टैंशिएशन**: `Person p;` (डिक्लेरेशन) स्टैक पर एक पॉइंटर स्लॉट आवंटित करता है जिसका मान `null` होता है और हीप में शून्य बाइट खर्च होते हैं; `p = new Person();` (इंस्टैंशिएशन) हीप पर मेमोरी आवंटित करता है, कंस्ट्रक्टर चलाता है और परिणामी संदर्भ `p` को सौंपता है।
>   2. **जावा हमेशा पूर्णतः पास-बाय-वैल्यू (Pass-by-Value) है**:
>      * **प्रिमिटिव्स**: बाइनरी मान सीधे मेथड के स्टैक फ्रेम में कॉपी होता है।
>      * **ऑब्जेक्ट रेफरेंस**: ऑब्जेक्ट का *मेमोरी पता (रेफरेंस हैंडल)* वैल्यू के रूप में कॉपी होता है।
>      * **फ़ील्ड म्यूटेशन बनाम री-असाइनमेंट**: संदर्भ के माध्यम से ऑब्जेक्ट के फ़ील्ड्स को बदलने पर (`p.setName("Bob")`) हीप का साझा ऑब्जेक्ट बदल जाता है; लेकिन पैरामीटर को दोबारा नया ऑब्जेक्ट सौंपने पर (`p = new Person("Eve")`) केवल स्थानीय स्टैक कॉपी बदलती है, कॉलर का ओरिजिनल वेरिएबल पूरी तरह अपरिवर्तित रहता है।
> * **रियल-वर्ल्ड सिस्टम:** जेवीएम एस्केप एनालिसिस (Scalar Replacement) और प्रोजेक्ट वाल्हाल्ला (Project Valhalla) वैल्यू ऑब्जेक्ट्स।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १३.६) में पूछा गया है:

*"जावा में ऑब्जेक्ट डिक्लेरेशन और इंस्टैंशिएशन के बीच अंतर समझाएं और यह सिद्ध करें कि जावा हमेशा पास-बाय-वैल्यू का पालन क्यों करता है।"*

## २. मेमोरी आवंटन: स्टैक बनाम हीप

* **डिक्लेरेशन (`Person p;`):** स्टैक पर केवल ४ या ८ बाइट्स का स्लॉट बनाता है।
* **इंस्टैंशिएशन (`new Person()`):** हीप पर वास्तविक ऑब्जेक्ट बनाता है और उसका पता लौटाता है।

## पास-बाय-वैल्यू का व्यावहारिक प्रमाण

```java
public class PassByValueProof {

    public static class User {
        public String name;
        public User(String name) { this.name = name; }
    }

    public static void attemptReassign(User u) {
        // केवल स्थानीय स्टैक कॉपी को बदलता है
        u = new User("नया उपयोगकर्ता");
    }

    public static void mutateObject(User u) {
        // हीप में मौजूद साझा ऑब्जेक्ट को बदलता है
        u.name = "संशोधित बॉब";
    }

    public static void attemptPrimitiveChange(int val) {
        val = 999;
    }

    public static void main(String[] args) {
        User user = new User("एलिस");

        attemptReassign(user);
        System.out.println("री-असाइन के बाद: " + user.name); // अभी भी "एलिस"

        mutateObject(user);
        System.out.println("म्यूटेशन के बाद: " + user.name);  // अब "संशोधित बॉब"

        int num = 42;
        attemptPrimitiveChange(num);
        System.out.println("प्रिमिटिव: " + num);             // अभी भी 42
    }
}
```

## विभिन्न प्रोग्रामिंग भाषाओं में तुलना

| भाषा | पासिंग मैकेनिज्म | क्या मेथड कॉलर के पॉइंटर को री-असाइन कर सकता है? |
|---|---|---|
| **जावा** | **पूर्णतः पास-बाय-वैल्यू** | **नहीं** (केवल स्थानीय स्टैक बदलता है)। |
| **C** | **पूर्णतः पास-बाय-वैल्यू** | **नहीं** (डबल पॉइंटर `Type**` की आवश्यकता होती है)। |
| **C++** | **पास-बाय-वैल्यू या पास-बाय-रेफरेंस** (`Type&`) | **हाँ** (यदि `&` रेफरेंस सिंटैक्स का उपयोग किया गया हो)। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: एस्केप एनालिसिस (Escape Analysis)

१. **स्केलर रिप्लेसमेंट (HotSpot C2):** यदि जेवीएम पाता है कि ऑब्जेक्ट मेथड से बाहर "एस्केप" नहीं होता है, तो वह हीप आवंटन को समाप्त करके ऑब्जेक्ट को सीधे सीपीयू रजिस्टर्स में बदल देता है।
२. **डिफेंसिव कॉपी:** किसी क्लास द्वारा परिवर्तनीय स्थिति लौटाते समय सुरक्षा के लिए हमेशा नई कॉपी लौटाएं (`return new Date(date.getTime())`)।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा
