> **टीएल;डीआर**
> * **किताब का सवाल:** C++ में वर्चुअल फ़ंक्शन कैसे काम करते हैं?
> * **मुख्य समाधान:** **Vtable और Vptr रनटाइम डायनामिक डिस्पैच**: (१) **वर्चुअल टेबल (`vtable`)**: प्रत्येक पॉलीमॉर्फिक क्लास के लिए कंपाइलर द्वारा निर्मित फ़ंक्शन पॉइंटर्स की एक स्टैटिक तालिका जो `.rodata` में संग्रहीत होती है; (२) **वर्चुअल पॉइंटर (`vptr`)**: प्रत्येक ऑब्जेक्ट इंस्टेंस के ऑफसेट ० पर एक छिपा हुआ पॉइंटर जो अपनी क्लास की `vtable` की ओर इंगित करता है; (३) **रनटाइम रिज़ॉल्यूशन**: `p->foo()` को कॉल करने पर सीपीयू $O(1)$ समय में `(p->vptr[index_foo])(p)` निष्पादित करता है; (४) **लागत**: प्रति ऑब्जेक्ट ८ बाइट्स अतिरिक्त मेमोरी और कंपाइलर फ़ंक्शन इनलाइनिंग का अभाव।
> * **रियल-वर्ल्ड सिस्टम:** गेम इंजन (Unreal Engine) और DirectX / COM ऑब्जेक्ट आर्किटेक्चर।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १२.४) में पूछा गया है:

*"सी++ में वर्चुअल फ़ंक्शंस की आंतरिक कार्यप्रणाली, vtable संरचना और डायनामिक डिस्पैच के प्रदर्शन प्रभावों की व्याख्या करें।"*

## २. मेमोरी लेआउट: Vptr और Vtable

जब कोई क्लास `virtual` मेथड घोषित करती है:
१. कंपाइलर क्लास के लिए एक स्टैटिक `vtable` तालिका बनाता है।
२. प्रत्येक ऑब्जेक्ट इंस्टेंस के शीर्ष पर ८ बाइट का एक छिपा हुआ `vptr` पॉइंटर जोड़ा जाता है।

रनटाइम पर कॉल:
$$\text{कॉल} = (\text{ऑब्जेक्ट}->\text{vptr}[\text{इंडेक्स}])(\text{ऑब्जेक्ट})$$

## प्रोडक्शन कार्यान्वयन

```cpp
#include <iostream>

class Shape {
public:
    int id;

    void printId() const {
        std::cout << "Shape ID: " << id << "\n";
    }

    virtual void draw() const {
        std::cout << "Drawing generic Shape\n";
    }

    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    double radius;

    void draw() const override {
        std::cout << "Drawing Circle with radius " << radius << "\n";
    }
};

void renderShape(const Shape* s) {
    s->draw(); // vtable द्वारा रनटाइम पर डायनामिक डिस्पैच
}
```

## प्रदर्शन और मेमोरी विश्लेषण

| कारक | लागत / प्रभाव | तकनीकी विवरण |
|---|---|---|
| **इंस्टेंस मेमोरी** | $+8\text{ Bytes}$ | ऑब्जेक्ट के ऑफसेट ० पर ६४-बिट `vptr` पॉइंटर। |
| **क्लास मेमोरी** | $8\text{ Bytes} \times N_{\text{methods}}$ | `.rodata` में प्रति क्लास एकल स्टैटिक `vtable`। |
| **कॉल विलंबता** | $\approx 2\text{ ns}$ | १ मेमोरी इनडायरेक्शन; फ़ंक्शन इनलाइनिंग अक्षम। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: स्टैटिक पॉलीमॉर्फिज्म (CRTP)

१. **CRTP (Curiously Recurring Template Pattern):** उच्च-आवृत्ति ट्रेडिंग और गेम इंजनों में `vptr` मेमोरी और इनडायरेक्शन लागत से बचने के लिए टेम्प्लेट द्वारा कंपाइल-टाइम पॉलीमॉर्फिज्म।
२. **ऑब्जेक्ट स्लाइसिंग (Object Slicing):** ऑब्जेक्ट को वैल्यू द्वारा पास करने (`void fn(Shape s)`) पर चाइल्ड क्लास के डेटा सदस्य कट जाते हैं और `vptr` बेस क्लास पर रीसेट हो जाता है। हमेशा पॉइंटर या संदर्भ (`Shape*` / `Shape&`) का उपयोग करें।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **कंस्ट्रक्टर/डिस्ट्रक्टर में वर्चुअल कॉल:** चाइल्ड क्लास अभी तक निर्मित नहीं हुई है (या नष्ट हो चुकी है), इसलिए रनटाइम पर केवल बेस क्लास का मेथड कॉल होता है।
