> **टीएल;डीआर**
> * **किताब की समस्या:** स्ट्रिंग में सभी खाली स्थानों को '%२०' से बदलें। आपको स्ट्रिंग की वास्तविक लंबाई और अंत में पर्याप्त खाली बफर दिया गया है।
> * **समाधान:** स्पेस गिनकर अंतिम लंबाई निकालना और पीछे से लिखते जाना ताकि कोई डेटा ओवरराइट न हो।
> * **रियल-वर्ल्ड सिस्टम:** वेब सर्वर में एचटीटीपी यूआरआई परसेंट-एन्कोडिंग।

## १. किताब का सवाल और संदर्भ

सीटीसीआई १.३ में `"Mr John Smith    ", १३` को बिना नया एरे बनाए `"Mr%२०John%२०Smith"` में बदला जाता है।

## २. पीछे से लिखने की कार्यप्रणाली

आगे से बदलने पर बाकी अक्षरों को बार-बार खिसकाना पड़ता है ($O(N^२)$), जबकि पीछे से लिखने पर यह $O(N)$ में पूरा होता है।

## प्रोडक्शन कार्यान्वयन

```java
// इन-प्लेस स्पेस रिप्लेसमेंट
public static void replaceSpaces(char[] str, int trueLength) {
    int spaces = 0;
    for (int i = 0; i < trueLength; i++) if (str[i] == ' ') spaces++;
    int index = trueLength + spaces * 2;
    for (int i = trueLength - 1; i >= 0; i--) {
        if (str[i] == ' ') {
            str[--index] = '0'; str[--index] = '2'; str[--index] = '%';
        } else {
            str[--index] = str[i];
        }
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| समय | `O(N)` | दो बार लीनियर स्कैन। |
| मेमोरी | `O(१)` | इन-प्लेस संशोधन। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### वास्तविक दुनिया में उपयोग: वेब सर्वर यूआरआई पार्सिंग

वेब सर्वर मेमोरी बचाने के लिए नेटवर्क बफर में ही सीधे यूआरएल एन्कोडिंग करते हैं।
