> **टीएल;डीआर**
> * **किताब का सवाल:** बेस क्लास में डिस्ट्रक्टर को वर्चुअल घोषित करने की आवश्यकता क्यों है?
> * **मुख्य समाधान:** **Vtable द्वारा पॉलीमॉर्फिक डिस्ट्रक्शन**: (१) जब किसी चाइल्ड क्लास ऑब्जेक्ट को बेस क्लास पॉइंटर के माध्यम से डिलीट किया जाता है (`Base* ptr = new Derived(); delete ptr;`), तो नॉन-वर्चुअल डिस्ट्रक्टर होने पर स्टैटिक बाइंडिंग के कारण केवल `Base::~Base()` कॉल होता है; (२) `Derived::~Derived()` कभी नहीं चलता, जिससे चाइल्ड क्लास द्वारा आवंटित हीप मेमोरी और फ़ाइल हैंडल लीक हो जाते हैं; (३) C++ मानक इसे **अपरिभाषित व्यवहार (Undefined Behavior)** घोषित करता है; (४) `virtual ~Base() = default;` घोषित करने पर कॉल `vtable` के माध्यम से जाती है, जिससे पहले `Derived::~Derived()` और फिर स्वचालित रूप से `Base::~Base()` निष्पादित होता है।
> * **रियल-वर्ल्ड सिस्टम:** Qt (`QObject`) और LLVM कंपाइलर एएसटी नोड्स।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १२.७) में पूछा गया है:

*"पॉलीमॉर्फिज्म का उपयोग करते समय बेस क्लास के डिस्ट्रक्टर का वर्चुअल होना क्यों अनिवार्य है?"*

## २. विनाश क्रम और संसाधन लीक

* **नॉन-वर्चुअल डिस्ट्रक्टर:** कंपाइलर पॉइंटर प्रकार (`Base*`) के आधार पर केवल बेस क्लास का डिस्ट्रक्टर चलाता है।
* **वर्चुअल डिस्ट्रक्टर:** कॉल रनटाइम पर `vtable` द्वारा चाइल्ड क्लास के डिस्ट्रक्टर पर भेजी जाती है, जिससे नीचे से ऊपर की ओर सभी संसाधन सही ढंग से मुक्त होते हैं।

## प्रोडक्शन कार्यान्वयन

```cpp
#include <iostream>

class BaseSafe {
public:
    BaseSafe() = default;
    virtual ~BaseSafe() {
        std::cout << "सुरक्षित बेस डिस्ट्रक्टर\n";
    }
};

class DerivedSafe : public BaseSafe {
private:
    int* buffer;
public:
    DerivedSafe() {
        buffer = new int[1000]; // हीप मेमोरी आवंटन
    }
    ~DerivedSafe() override {
        delete[] buffer; // मेमोरी सुरक्षित रूप से मुक्त
        std::cout << "सुरक्षित चाइल्ड डिस्ट्रक्टर: मेमोरी मुक्त!\n";
    }
};
```

## तुलनात्मक परिदृश्य

| परिदृश्य | निष्पादित कोड | क्या चाइल्ड डिस्ट्रक्टर चला? | परिणाम |
|---|---|---|---|
| नॉन-वर्चुअल बेस | `delete (Base*)ptr;` | **नहीं** | हीप मेमोरी लीक + अपरिभाषित व्यवहार। |
| वर्चुअल बेस | `delete (Base*)ptr;` | **हाँ** | संपूर्ण मेमोरी स्वच्छ रूप से पुनः प्राप्त। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: C++ कोर दिशानिर्देश (C.35)

१. **दिशानिर्देश नियम C.35:** बेस क्लास का डिस्ट्रक्टर या तो सार्वजनिक और वर्चुअल होना चाहिए, या संरक्षित (protected) और गैर-वर्चुअल।
२. **एसटीएल क्लासेस:** `std::vector` जैसी क्लासेस में वर्चुअल डिस्ट्रक्टर नहीं होते; उनसे पब्लिक इनहेरिटेंस करके बेस पॉइंटर से डिलीट करना गंभीर बग बनाता है।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **प्योर वर्चुअल डिस्ट्रक्टर:** `virtual ~Base() = 0;` क्लास को एब्सट्रैक्ट बनाता है, लेकिन इसकी बॉडी `Base::~Base() {}` का होना अनिवार्य है।
