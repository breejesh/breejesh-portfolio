> **टीएल;डीआर**
> * **किताब का सवाल:** आपके पास बास्केटबॉल हूप है और आप दो में से एक खेल खेल सकते हैं। खेल १: आपको टोकरी में डालने के लिए १ शॉट मिलता है। खेल २: आपको ३ शॉट मिलते हैं और आपको ३ में से २ शॉट लगाने होते हैं। यदि $p$ किसी शॉट को लगाने की संभावना है, तो $p$ के किन मानों के लिए आपको कौन सा खेल चुनना चाहिए?
> * **मुख्य समाधान:** **द्विपद प्रायिकता असमानता**: $P(\text{खेल १}) = p$। $P(\text{खेल २}) = 3p^2 - 2p^3$। असमानता हल करने पर: $3p^2 - 2p^3 > p \implies (2p - 1)(p - 1) < 0 \implies p > 0.5$। यदि **$p < 0.5$ है तो खेल १ चुनें**, यदि **$p > 0.5$ है तो खेल २ चुनें**, और $p \in \{0, 0.5, 1\}$ होने पर कोई भी खेल चुनें।
> * **रियल-वर्ल्ड सिस्टम:** वितरित सर्वसम्मति में कोरम बहुमत वोटिंग (Raft/Paxos) और ए/बी परीक्षण सांख्यिकी।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या ६.२) में पूछा गया है:

*"शॉट लगाने की प्रायिकता p होने पर, १-शॉट खेल और ३ में से २-शॉट खेल के बीच चयन के लिए p की सीमाएं क्या हैं?"*

## २. गणितीय विश्लेषण

१. **खेल १ जीतने की प्रायिकता:** $P(\text{खेल १}) = p$
२. **खेल २ जीतने की प्रायिकता:** २ या ३ शॉट लगाना:
   $$P(\text{खेल २}) = 3p^2(1 - p) + p^3 = 3p^2 - 2p^3$$
३. **तुलना:**
   $$3p^2 - 2p^3 > p \implies 2p^2 - 3p + 1 < 0 \implies (2p - 1)(p - 1) < 0$$
   चूंकि $p < 1$ है, $(p - 1)$ नकारात्मक होगा, जिससे $(2p - 1) > 0 \implies p > 0.5$ आवश्यक है।

## प्रोडक्शन कार्यान्वयन

```java
public class BasketballGame {
    /**
     * शॉट प्रायिकता p के आधार पर खेल 1 या खेल 2 चुनता है।
     * समय जटिलता: O(1)
     * स्पेस जटिलता: O(1)
     */
    public static int pickGame(double p) {
        if (p < 0.0 || p > 1.0) {
            throw new IllegalArgumentException("प्रायिकता 0 और 1 के बीच होनी चाहिए");
        }

        if (p > 0.5 && p < 1.0) {
            return 2;
        } else if (p < 0.5 && p > 0.0) {
            return 1;
        } else {
            return 0; // दोनों खेल समान हैं (p = 0, 0.5, या 1.0)
        }
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| मूल्यांकन समय | `O(१)` | सीधा फ्लोटिंग-पॉइंट तुलना ऑपरेशन। |
| सहायक मेमोरी | `O(१)` | शून्य मेमोरी आवंटन। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: वितरित प्रणालियों में कोरम

१. **वितरित सर्वसम्मति कोरम (Raft / Paxos):** जब व्यक्तिगत नोड उपलब्धता $p > 0.5$ होती है, तो बहुसंख्यक क्लस्टर कोरम ($2f + 1$) समग्र उपलब्धता को बढ़ाता है। यदि $p < 0.5$ हो, तो अधिक नोड्स जोड़ने से विफलता की दर बढ़ती है।
२. **सर्किट ब्रेकर्स:** नमूनों के आधार पर फेलओवर निर्णय।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **$p = 0.5$:** दोनों खेलों में जीतने की प्रायिकता बिल्कुल ५०% ($0.5$) होती है।
२. **सीमाएं ($p = 0$ या $p = 1$):** दोनों में क्रमशः ०% या १००% संभावना।
