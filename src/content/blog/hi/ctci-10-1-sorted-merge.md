> **टीएल;डीआर**
> * **किताब का सवाल:** आपको दो क्रमबद्ध ऐरे $A$ और $B$ दिए गए हैं, जहाँ $A$ के अंत में $B$ को रखने के लिए पर्याप्त बड़ा बफर है। $B$ को $A$ में क्रमबद्ध तरीके से मर्ज करने के लिए एक विधि लिखें।
> * **मुख्य समाधान:** **रिवर्स थ्री-पॉइंटर इन-प्लेस मर्जिंग**: (१) सूचक `indexA = lastA - 1`, `indexB = lastB - 1` और लेखन सूचक `indexMerged = lastA + lastB - 1` सेट करें; (२) पीछे से तत्वों की तुलना करें और बड़े मान को $A[\text{indexMerged}]$ में कॉपी करें; (३) यदि $B$ में तत्व शेष हैं, तो उन्हें सीधे $A$ में स्थानांतरित करें; (४) यह बिना अतिरिक्त ऐरे या शिफ्टिंग के **$O(A + B)$ समय** और **$O(१)$ स्पेस** में पूरा होता है।
> * **रियल-वर्ल्ड सिस्टम:** LSM-ट्री में SSTable संघनन (RocksDB) और डेटाबेस कर्सर मर्जिंग।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १०.१) में पूछा गया है:

*"क्रमबद्ध ऐरे B को ऐरे A में इन-प्लेस मर्ज करें, जहां A के अंत में B के आकार जितना खाली स्थान उपलब्ध है।"*

## २. रिवर्स मर्जिंग तर्क

सामने से मर्ज करने पर $A$ के तत्वों को बार-बार दाईं ओर शिफ्ट करना होगा ($O(N^2)$)।

खाली बफर के अंतिम छोर से शुरुआत करके:
$$\text{indexMerged} = \text{lastA} + \text{lastB} - 1$$
सबसे बड़े तत्वों को पहले खाली जगह में रखा जाता है, जिससे $A$ के अपठित तत्व कभी अधिलेखित (overwrite) नहीं होते।

## प्रोडक्शन कार्यान्वयन

```java
public class SortedMerge {
    /**
     * ऐरे B को ऐरे A में इन-प्लेस क्रमबद्ध तरीके से मर्ज करता है।
     * समय जटिलता: O(A + B)
     * स्पेस जटिलता: O(1)
     */
    public static void merge(int[] a, int[] b, int lastA, int lastB) {
        int indexA = lastA - 1; // a का अंतिम तत्व
        int indexB = lastB - 1; // b का अंतिम तत्व
        int indexMerged = lastB + lastA - 1; // मर्ज किए गए ऐरे का अंत

        while (indexB >= 0) {
            if (indexA >= 0 && a[indexA] > b[indexB]) {
                a[indexMerged] = a[indexA];
                indexA--;
            } else {
                a[indexMerged] = b[indexB];
                indexB--;
            }
            indexMerged--;
        }
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| समय जटिलता | `O(A + B)` | ठीक $lastA + lastB$ रैखिक तुलनाएं। |
| सहायक मेमोरी | `O(१)` | केवल ३ पूर्णांक पॉइंटर चर। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: एलएसएम-ट्री कॉम्पेक्शन (RocksDB)

१. **SSTable कर्सर मर्जिंग:** RocksDB और Cassandra बिना किसी अतिरिक्त मेमोरी आवंटन के क्रमबद्ध फ़ाइल खंडों को स्ट्रीम में मर्ज करते हैं।
२. **मेमोरी बफर सुरक्षा:** रिवर्स इंडेक्सिंग बफर ओवरराइट से बचाती है।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **ऐरे B खाली होना ($lastB = 0$):** लूप तुरंत समाप्त होता है; $A$ अपरिवर्तित रहता है।
२. **ऐरे A खाली होना ($lastA = 0$):** $B$ के सभी तत्व सीधे $A$ में कॉपी हो जाते हैं।
