> **टीएल;डीआर**
> * **किताब का सवाल:** एक थ्रेड (Thread) और प्रोसेस (Process) में क्या अंतर है?
> * **मौलिक अंतर:**
>   1. **प्रोसेस**: अपने स्वयं के पृथक वर्चुअल एड्रेस स्पेस (Page Tables), फाइल डिस्क्रिप्टर टेबल और प्रोसेस कंट्रोल ब्लॉक (PCB) के साथ एक स्वतंत्र निष्पादन इकाई। संचार के लिए अंतर-प्रक्रिया संचार (IPC: पाइप्स, सॉकेट्स, शेयर्ड मेमोरी) की आवश्यकता होती है।
>   2. **थ्रेड**: एक ही प्रोसेस के भीतर निष्पादित होने वाली हल्की इकाई (TCB)। सभी थ्रेड्स समान हीप, कोड और खुली फाइलों को साझा करते हैं, लेकिन प्रत्येक का अपना **प्रोग्राम काउंटर (PC), सीपीयू रजिस्टर्स और स्टैक (Stack)** होता है।
>   3. **विफलता का दायरा**: एक थ्रेड के क्रैश होने पर पूरी प्रोसेस बंद हो जाती है; जबकि एक प्रोसेस के क्रैश होने पर अन्य प्रोसेस अप्रभावित रहती हैं।
> * **रियल-वर्ल्ड सिस्टम:** गूगल क्रोम में मल्टी-प्रोसेस टैब आइसोलेशन और जावा जेवीएम मल्टी-थ्रेडिंग।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १५.१) में पूछा गया है:

*"ऑपरेटिंग सिस्टम में प्रोसेस और थ्रेड्स के बीच मेमोरी, निष्पादन और संसाधन साझाकरण के आधार पर अंतर स्पष्ट करें।"*

## २. मेमोरी आर्किटेक्चर

* **प्रोसेस:** हार्डवेयर MMU द्वारा सुरक्षित और पूरी तरह पृथक वर्चुअल मेमोरी।
* **थ्रेड:** मूल प्रोसेस की हीप मेमोरी को साझा करता है, लेकिन इसका अपना निजी स्टैक होता है।

## प्रोडक्शन कार्यान्वयन

```c
#include <stdio.h>
#include <unistd.h>
#include <pthread.h>
#include <sys/wait.h>

int shared_val = 100;

void* thread_func(void* arg) {
    shared_val += 50; // हीप मेमोरी में साझा परिवर्तन
    printf("थ्रेड: shared_val = %d\n", shared_val);
    return NULL;
}

int main() {
    pthread_t tid;
    pthread_create(&tid, NULL, thread_func, NULL);
    pthread_join(tid, NULL);
    printf("मेन थ्रेड: %d (साझा मेमोरी)\n", shared_val);

    pid_t pid = fork();
    if (pid == 0) {
        shared_val += 500; // चाइल्ड प्रोसेस की निजी कॉपी
        printf("चाइल्ड प्रोसेस: %d\n", shared_val);
        _exit(0);
    } else {
        wait(NULL);
        printf("पैरेंट प्रोसेस: %d (पृथक मेमोरी)\n", shared_val);
    }
    return 0;
}
```

## तुलनात्मक तालिका

| मापदंड | प्रोसेस (Process) | थ्रेड (Thread) |
|---|---|---|
| **एड्रेस स्पेस** | पूरी तरह पृथक वर्चुअल मेमोरी। | समान प्रोसेस के भीतर साझा। |
| **निर्माण लागत** | भारी ($O(\text{fork})$ पेज टेबल क्लोनिंग)। | हल्की (स्टैक आवंटन $\approx 1\text{MB}$)। |
| **कॉन्टेक्स्ट स्विच** | धीमा (सीपीयू TLB कैश को फ्लश करता है)। | तीव्र (TLB मैपिंग बरकरार रहती है)। |
| **संचार (IPC)** | IPC आवश्यक (पाइप्स, सॉकेट्स)। | हीप मेमोरी में सीधा पठन/लेखन। |
| **क्रैश प्रभाव** | सीमित (अन्य प्रोसेस सुरक्षित रहती हैं)। | घातक (एक थ्रेड क्रैश पूरी प्रोसेस बंद करता है)। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: ब्राउज़र और वेब सर्वर

१. **गूगल क्रोम आर्किटेक्चर:** प्रत्येक टैब को एक अलग प्रोसेस में चलाता है ताकि एक टैब का क्रैश पूरे ब्राउज़र को बंद न करे।
२. **Nginx मास्टर-वर्कर मॉडल:** अत्यधिक दक्षता के लिए प्रति कोर एकल-थ्रेडेड वर्कर प्रोसेस का उपयोग।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **ज़ॉम्बी प्रोसेस:** समाप्त हो चुकी चाइल्ड प्रोसेस जिसे पैरेंट द्वारा `wait()` नहीं किया गया है, कर्नल प्रोसेस टेबल में स्थान घेरती है।
