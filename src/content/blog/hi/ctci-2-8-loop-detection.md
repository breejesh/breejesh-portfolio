> **टीएल;डीआर**
> * **किताब का सवाल:** एक वृत्ताकार (सर्कुलर) लिंक्ड लिस्ट दी गई है, ऐसा एल्गोरिदम लागू करें जो लूप की शुरुआत वाले नोड को लौटाए।
> * **मुख्य समाधान:** फ़्लॉइड का टॉर्टॉयज एंड हेयर एल्गोरिदम: (१) धीमे पॉइंटर को १ कदम और तेज पॉइंटर को २ कदम आगे बढ़ाएं जब तक वे लूप के भीतर टकरा न जाएं; (२) धीमे पॉइंटर को लिस्ट के हेड पर रीसेट करें; (३) दोनों को १-१ कदम आगे बढ़ाएं जब तक वे लूप की सटीक शुरुआत पर दोबारा न मिलें ($O(N)$ समय और $O(१)$ स्पेस)।
> * **रियल-वर्ल्ड सिस्टम:** डिस्ट्रिब्यूटेड डेडलॉक का पता लगाना, डेटाबेस ट्रांजेक्शन निर्भरता ग्राफ और पॉइंटर सैनिटाइजर।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या २.८) में, हमें एक ऐसी लिंक्ड लिस्ट दी गई है जिसमें एक लूप है (एक भ्रष्ट लिस्ट जहां किसी नोड का `next` पॉइंटर पिछले नोड की ओर इशारा करता है)। हमें बिना किसी अतिरिक्त मेमोरी के लूप की शुरुआत वाले सटीक नोड का पता लगाना है।

## २. फ़्लॉइड के चक्र का पता लगाने का गणितीय प्रमाण

मान लें कि लूप शुरू होने से पहले $k$ नोड्स हैं, और लूप की लंबाई $C$ है:
१. जब धीमा पॉइंटर (`Slow`) लूप में प्रवेश करता है ($k$ चरणों के बाद), तो तेज पॉइंटर (`Fast`) कदम $२k$ पर होता है (यानी लूप के अंदर $k \pmod C$ चरण)।
२. `Fast` लूप के भीतर `Slow` से $C - (k \pmod C)$ कदम पीछे है। चूंकि `Fast` प्रति चरण १ कदम की गति से अंतर कम करता है, इसलिए वे $C - (k \pmod C)$ चरणों के बाद आपस में टकराएंगे।
३. यह टकराव बिंदु लूप की शुरुआत से ठीक $k$ कदम की दूरी पर होता है।
४. इसलिए, `Fast` को टकराव बिंदु पर रखकर और `Slow` को वापस `head` पर ले जाकर, दोनों को १-१ कदम आगे बढ़ाने पर वे ठीक $k$ चरणों के बाद लूप के प्रारंभिक बिंदु पर मिलते हैं।

## प्रोडक्शन कार्यान्वयन

```java
public class LoopDetection {
    public static class LinkedListNode {
        public int data;
        public LinkedListNode next;
        public LinkedListNode(int d) { this.data = d; }
    }

    public static LinkedListNode findBeginning(LinkedListNode head) {
        LinkedListNode slow = head;
        LinkedListNode fast = head;

        // लूप के भीतर मिलन बिंदु खोजें
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                break; // टकराव मिल गया
            }
        }

        // त्रुटि जांच: कोई लूप नहीं है
        if (fast == null || fast.next == null) {
            return null;
        }

        // Slow को Head पर ले जाएं, Fast को मिलन बिंदु पर रखें
        slow = head;
        while (slow != fast) {
            slow = slow.next;
            fast = fast.next;
        }

        // दोनों अब लूप के शुरुआती नोड पर हैं
        return fast;
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| समय जटिलता | `O(N)` | तेज पॉइंटर अधिकतम $२N$ कदम चलता है। |
| सहायक मेमोरी | `O(१)` | बिना किसी हैशसेट के केवल दो पॉइंटर रजिस्टर। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: डेटाबेस ट्रांजेक्शन और डेडलॉक

पोस्टग्रेएसक्यूएल (PostgreSQL) ट्रांजेक्शन मैनेजर और डिस्ट्रिब्यूटेड सर्वसम्मति इंजन सर्कुलर वेट डेडलॉक का पता लगाने के लिए $O(१)$ स्पेस में फ़्लॉइड के चक्र एल्गोरिदम का उपयोग करते हैं।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **लिस्ट में कोई लूप न होना:** `fast` पॉइंटर `null` पर पहुंचता है और $O(N)$ में `null` लौटाता है।
२. **लूप का हेड से ही शुरू होना:** शून्य चरणों में सीधे हेड लौटाता है।
