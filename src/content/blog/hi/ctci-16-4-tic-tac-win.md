> **टीएल;डीआर**
> * **किताब का सवाल:** यह पता लगाने के लिए एक एल्गोरिदम डिज़ाइन करें कि क्या किसी ने टिक-टैक-टो (Tic-Tac-Toe) का खेल जीत लिया है।
> * **मुख्य समाधान:**
>   1. **बार-बार प्रश्न ($3 \times 3$)**: बेस-३ पूर्णांक हैश द्वारा सभी $३^९ = १९,६८३$ संभावित बोर्ड स्थितियों को प्रीकंप्यूट करें। यह **$O(1)$ समय** में तत्काल उत्तर देता है।
>   2. **सामान्य $N \times N$ बोर्ड**: $N$ पंक्तियों, $N$ स्तंभों और २ विकर्णों को **$O(N)$ समय** में स्कैन करें।
>   3. **इंक्रीमेंटल मूव ट्रैकिंग ($N \times N$)**: प्रत्येक चाल पर पंक्ति, स्तंभ और विकर्ण काउंटरों को अपडेट करें। यह प्रति चाल **$O(1)$ समय** में जीत की पुष्टि करता है।
> * **रियल-वर्ल्ड सिस्टम:** टर्न-आधारित गेम सर्वर और जोब्रिस्ट हैशिंग (Zobrist Hashing)।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या १६.४) में पूछा गया है:

*"टिक-टैक-टो में विजेता का निर्धारण करने के लिए स्थिर ३x३ बोर्ड और गतिशील NxN बोर्ड्स के लिए कुशल एल्गोरिदम डिज़ाइन करें।"*

## २. समाधान वर्गीकरण

* **बेस-३ प्रीकंप्यूटेशन:** ३x३ बोर्ड को एक संख्या ($०$ से $१९,६८२$) में बदलता है।
* **इंक्रीमेंटल काउंटर:** खिलाड़ी X के लिए $+१$ और O के लिए $-१$ जोड़ता है; मान $\pm N$ होने पर तुरंत जीत घोषित होती है।

## प्रोडक्शन कार्यान्वयन

```java
public class TicTacToe {
    public enum Piece { Empty, X, O }

    public static class TicTacToeGame {
        private final int n;
        private final int[] rows;
        private final int[] cols;
        private int diagonal = 0;
        private int antiDiagonal = 0;

        public TicTacToeGame(int n) {
            this.n = n;
            this.rows = new int[n];
            this.cols = new int[n];
        }

        public Piece move(int r, int c, Piece player) {
            if (player == Piece.Empty) return Piece.Empty;
            int val = (player == Piece.X) ? 1 : -1;

            rows[r] += val;
            cols[c] += val;
            if (r == c) diagonal += val;
            if (r + c == n - 1) antiDiagonal += val;

            int target = (player == Piece.X) ? n : -n;
            if (rows[r] == target || cols[c] == target || diagonal == target || antiDiagonal == target) {
                return player;
            }
            return Piece.Empty;
        }
    }
}
```

## जटिलता विश्लेषण

| रणनीति | प्रति चाल समय | सहायक मेमोरी | सर्वोत्तम उपयोग |
|---|---|---|---|
| **इंक्रीमेंटल काउंटर** | **$O(1)$** | $O(N)$ | लाइव रीयल-टाइम गेमप्ले। |
| **पूर्ण बोर्ड स्कैन** | $O(N)$ | $O(1)$ | स्टैंडअलोन बोर्ड सत्यापन। |
| **बेस-३ प्रीकंप्यूटेशन** | **$O(1)$** | $१९.७\text{ KB}$ | स्थिर ३x३ बोर्ड। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: जोब्रिस्ट हैशिंग और बिटबोर्ड्स

१. **जोब्रिस्ट हैशिंग (Zobrist Hashing):** मिनीमैक्स गेम ट्री में समान स्थितियों के पुन: मूल्यांकन से बचने के लिए बोर्ड स्थिति को ६४-बिट पूर्णांक में मैप करना।
२. **बिटबोर्ड्स:** बोर्ड को ६४-बिट `long` में संग्रहीत करके बिटवाइज़ ऑपरेशंस द्वारा एकल सीपीयू चक्र में जीत की जांच करना।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **ड्रॉ स्थिति:** यदि कोई विजेता नहीं है और सभी सेल भरे हुए हैं, तो गेम को ड्रॉ घोषित किया जाता है।
