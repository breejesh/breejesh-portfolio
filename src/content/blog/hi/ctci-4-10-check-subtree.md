> **टीएल;डीआर**
> * **किताब का सवाल:** $T_1$ और $T_2$ दो बहुत बड़े बाइनरी ट्री हैं, जिसमें $T_1$, $T_2$ से बहुत बड़ा है। यह निर्धारित करने के लिए एक एल्गोरिदम बनाएं कि क्या $T_2$, $T_1$ का एक सबट्री है।
> * **मुख्य समाधान:** **ट्री सर्च मैचिंग**: $T_1$ में उन नोड्स की खोज करें जिनका मान $T_2$ के रूट से मेल खाता है। प्रत्येक उम्मीदवार के लिए `matchTree(r1, r2)` चलाएं जो संरचना और मानों की तुलना करता है ($O(N + kM)$ समय और $O(\log N + \log M)$ स्पेस बिना विशाल स्ट्रिंग आवंटन के)।
> * **रियल-वर्ल्ड सिस्टम:** एएसटी (AST) सिंटैक्स कोड लिंटिंग (Semgrep/ESLint) और कंपाइलर अनुकूलन में सामान्य सब-एक्सप्रेशन निष्कासन।

## १. किताब का सवाल और संदर्भ

*क्रैकिंग द कोडिंग इंटरव्यू* (समस्या ४.१०) में पूछा गया है:

*"T1 और T2 दो बहुत बड़े बाइनरी ट्री हैं, जिसमें T1 बहुत बड़ा है। यह निर्धारित करने के लिए एक एल्गोरिदम बनाएं कि क्या T2, T1 का सबट्री है।"*

## २. दृष्टिकोणों की तुलना

१. **स्ट्रिंग सीरियलाइज़ेशन:** दोनों पेड़ों को स्ट्रिंग में बदलना (नल नोड्स के लिए `X` मार्कर के साथ) और सबस्ट्रिंग मैचिंग चलाना। इसमें $O(N + M)$ अतिरिक्त मेमोरी की आवश्यकता होती है, जो करोड़ों नोड्स वाले पेड़ों में मेमोरी क्रैश का कारण बन सकती है।
२. **रिकर्सिव ट्री सर्च मैचिंग:** $T_1$ में उम्मीदवार रूट नोड्स खोजना और `matchTree` के माध्यम से तुलना करना। इसमें केवल $O(\log N + \log M)$ स्टैक मेमोरी लगती है।

## प्रोडक्शन कार्यान्वयन

```java
public class CheckSubtree {
    public static class TreeNode {
        public int val;
        public TreeNode left;
        public TreeNode right;
        public TreeNode(int x) { this.val = x; }
    }

    /**
     * जांचता है कि क्या t2, t1 का सबट्री है।
     * समय जटिलता: O(N + kM)
     * स्पेस जटिलता: O(log N + log M)
     */
    public static boolean containsTree(TreeNode t1, TreeNode t2) {
        if (t2 == null) return true; // खाली पेड़ हमेशा सबट्री होता है
        return subTree(t1, t2);
    }

    private static boolean subTree(TreeNode r1, TreeNode r2) {
        if (r1 == null) {
            return false;
        } else if (r1.val == r2.val && matchTree(r1, r2)) {
            return true;
        }
        return subTree(r1.left, r2) || subTree(r1.right, r2);
    }

    private static boolean matchTree(TreeNode r1, TreeNode r2) {
        if (r1 == null && r2 == null) {
            return true;
        } else if (r1 == null || r2 == null) {
            return false;
        } else if (r1.val != r2.val) {
            return false;
        } else {
            return matchTree(r1.left, r2.left) && matchTree(r1.right, r2.right);
        }
    }
}
```

## जटिलता और मेमोरी विश्लेषण

| मापदंड | जटिलता | तकनीकी विवरण |
|---|---|---|
| समय जटिलता | `O(N + kM)` | $T_1$ में $N$ नोड्स, $T_2$ में $M$ नोड्स और $k$ मिलान वाले उम्मीदवार रूट। |
| सहायक मेमोरी | `O(\log N + \log M)` | संतुलित पेड़ों पर स्टैक मेमोरी की गहराई। |

## वास्तविक दुनिया में सिस्टम इंजीनियरिंग उपयोग

### प्रोडक्शन सिस्टम आर्किटेक्चर: सिंटैक्स ट्री पैटर्न मैचिंग

१. **स्टैटिक कोड एनालिसिस (Semgrep / ESLint):** कोडबेस में सुरक्षा त्रुटियों की पहचान के लिए एएसटी सबट्री मैचिंग।
२. **कंपाइलर ऑप्टिमाइज़ेशन (LLVM):** दोहराव वाले अभिव्यक्तियों को हटाने के लिए समान सबट्री खोजना।

## सीमा स्थितियां और प्रोडक्शन सुरक्षा

१. **$T_2$ का null होना:** तुरंत `true` लौटाता है।
२. **$T_1$ का null और $T_2$ का गैर-null होना:** `false` लौटाता है।
